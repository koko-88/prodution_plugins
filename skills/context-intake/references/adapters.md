# Domain adapters and specialist boundaries

Use [the detailed specialist routes](coverage-specialists.md) for a relevant
source-specific distinction and [evidence-route boundaries](coverage-routing.md)
for connector or provider exclusions. Do not run the originating lifecycles.

Adapters receive the same canonical Intake Handoff; they do not change its schema,
destination or ownership. Honor an explicit factory. If inferred, cite the evidence
and retain uncertainty. Capability presence, catalog exposure, connection,
operability and verified results are separate claims.

## Software and evidence acquisition

When a bounded fact matters to framing, a relevant symbol/config read may use
Serena, a narrow repo search or existing graph evidence. Record freshness and
coverage; a graph cannot prove completeness outside its indexed scope. Repomix
packaging writes output and full codebase mapping are downstream acquisition.
Context7/official documentation can resolve versioned external facts; unavailable
tools become routed gaps. Do not trigger any full acquisition workflow. REA
artifact/runtime evidence and Reference Reconstruction observation/inference/
coverage discipline are useful when source code alone cannot establish reality;
binary inspection, reference capture and reconstruction stay specialist work.

For a bug, separate current behavior, expected owner intent, minimal trigger,
reproduction evidence, suspected path and confidence. A hypothesis is not a
verified cause. Intake does not start a fix, test suite or investigation lifecycle.

## Automation and process factories

Use trigger -> action -> beneficiary/outcome as a completeness lens. Discover
available integration candidates before asking a person to choose implementation
facts. Zero candidates may require a research gap; one adequate candidate need
not create a needless menu; several candidates require an actual open decision.
Preserve deferred inputs and owner-visible behavior. These Cursor automate and
control-loop techniques do not authorize creating automations or workflows.

For n8n, record human/system actors, timing and expected behavior; route node,
credential, execution, rate-limit and retry capability facts to its factory. The
shared entry never constructs nodes, requests credentials or prescribes a workflow
artifact. Other process domains use their own vocabulary and source owners.

## UI/UX and developer experience

Use real actor goals, journey transitions and consequential loading/empty/error/
success/partial/disabled/recovery states where relevant. Motivations, touchpoints
and emotions are hypotheses until grounded in actual stakeholder evidence.
Non-leading usability tasks can inform empirical-validation pointers; synthetic
personas cannot answer owner questions. Route fidelity, assets, reference capture,
interaction details and implementation to UI/UX acquisition.

Cursor Figma's bounded architecture check is a useful optional limit: inspect only
the relevant context, with an explicit file/import expansion budget. Its source
20-file/one-import-level choice is a specialist method, not a mandatory universal
quota. Hidden workflow assets do not establish active Codex capability.
For developer products, a discover/install/first-success/use/debug/upgrade journey
may expose important actors and failures. Do not run DX/design QA during intake.

## Stakeholder, analytics and security sources

Find the actual source owner for consequential knowledge. A sales summary is not
proof of a customer quotation: verify speaker, exact context and source support
before attributing a claim. Analytics context authority depends on the specific
metric/definition/decision, not job title or document recency alone. Preserve
contradictory claims and missing access. Existing Drive/tracker/chat connectors
are optional evidence routes; reading authorization does not authorize messaging.

Security policies constrain requirements and decision ownership. They do not turn
intake into a scan or authorize production access. Record genuine security/privacy
constraints and route specialist verification. Cached proprietary plugin content
is referenced and distilled in fresh wording, not redistributed as instructions.

## Superpowers and other ecosystems

The older 6.3.0 brainstorming copy distinguishes spike, bounded and architectural
discovery. The 6.4.2 copy adds an explicit shared-understanding correction step
before proceeding. Use proportional discovery and propagate corrections through
dependent claims. The current catalog exposes 6.4.2; the earlier audit's exposure
of 6.3.0 is historical. Neither source's design approvals, plan transitions,
prototype creation or QA lifecycle is automatically invoked here.

Cline Plan/Act and ask-question mechanisms are interface/lifecycle primitives;
OpenCode binary presence does not verify a native intake method. Synthetic-data
dimension design helps vary scenarios in evaluations; generated examples never
establish real stakeholder rules or production frequency. Existing factories
remain untouched and can accept the common handoff through an explicit caller
instruction; no implicit chain of specialist skills is required.
